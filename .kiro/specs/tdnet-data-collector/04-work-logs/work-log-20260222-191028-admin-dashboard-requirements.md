## 作業内容

### 1. 背景

ユーザーから以下の要望を受けた：
- 実装した機能を実行できる管理画面を追加したい
- データの状態や内容も管理したい

### 2. 追加する要件

#### 要件19: 管理画面（Admin Dashboard）

**目的:**
- システムの全機能を統合的に管理・実行できるWebインターフェースを提供
- データの状態監視と内容確認を可能にする
- 運用タスクを効率化し、手動スクリプト実行を削減

**主要機能:**

1. **データ収集管理**
   - オンデマンド収集の実行（日付範囲指定）
   - バッチ収集の手動トリガー
   - 収集ジョブの実行状態監視（進行中、完了、失敗）
   - 実行履歴の表示（過去30日分）

2. **データ状態監視**
   - 収集済みデータの統計情報（総件数、日別件数、企業別件数）
   - 最新収集日時の表示
   - データ品質メトリクス（成功率、失敗率、エラー種別）
   - ストレージ使用量（DynamoDB、S3）

3. **データ内容管理**
   - 開示情報の検索・フィルタリング（既存のWebダッシュボード機能を統合）
   - 個別レコードの詳細表示
   - PDFプレビュー機能
   - データの手動削除・修正機能（管理者権限）

4. **システム管理**
   - APIキーの管理（生成、ローテーション、無効化）
   - 環境変数の確認・編集
   - Lambda関数の実行状態確認
   - CloudWatchログの表示

5. **監視・アラート**
   - エラーログの一覧表示
   - DLQメッセージの確認・再処理
   - CloudWatchアラームの状態表示
   - システムヘルスチェック

### 3. 実装方針

#### アーキテクチャ
- **フロントエンド:** React（既存のdashboardを拡張）
- **バックエンド:** API Gateway + Lambda（既存のAPIを拡張）
- **認証:** APIキー認証（既存の仕組みを利用）
- **権限管理:** 管理者用APIキーと一般ユーザー用APIキーを分離

#### 新規APIエンドポイント

1. **収集管理API**
   - `POST /admin/collect/trigger` - オンデマンド収集の実行
   - `GET /admin/collect/status/{executionId}` - 実行状態の取得
   - `GET /admin/collect/history` - 実行履歴の取得

2. **データ管理API**
   - `GET /admin/data/stats` - データ統計情報の取得
   - `GET /admin/data/quality` - データ品質メトリクスの取得
   - `DELETE /admin/data/{disclosureId}` - データの削除

3. **システム管理API**
   - `GET /admin/system/health` - システムヘルスチェック
   - `GET /admin/system/logs` - ログの取得
   - `GET /admin/dlq/messages` - DLQメッセージの取得
   - `POST /admin/dlq/reprocess` - DLQメッセージの再処理

#### UI設計

1. **ダッシュボードホーム**
   - システム概要（総データ件数、最新収集日時、ストレージ使用量）
   - 実行中のジョブ一覧
   - 最近のエラー一覧

2. **データ収集ページ**
   - 収集実行フォーム（日付範囲選択、実行ボタン）
   - 実行履歴テーブル（実行ID、開始日時、終了日時、ステータス、成功率）
   - 実行状態の詳細表示（進捗バー、ログ表示）

3. **データ管理ページ**
   - 統計情報カード（総件数、日別グラフ、企業別ランキング）
   - データ品質メトリクス（成功率、エラー種別の円グラフ）
   - 検索・フィルタリング機能（既存のWebダッシュボードを統合）

4. **システム管理ページ**
   - Lambda関数の状態一覧
   - CloudWatchアラームの状態
   - APIキー管理テーブル
   - 環境変数の表示・編集

5. **ログ・監視ページ**
   - エラーログテーブル（時刻、エラー種別、メッセージ、スタックトレース）
   - DLQメッセージ一覧（メッセージID、受信日時、再処理ボタン）
   - CloudWatchログストリームの表示

### 4. セキュリティ考慮事項

- 管理者用APIキーは別途生成し、Secrets Managerで管理
- 管理画面へのアクセスはIPアドレス制限を推奨（WAFルール）
- データ削除・修正操作は監査ログに記録（CloudTrail）
- 環境変数の表示時は機密情報をマスク

### 5. コスト影響

- Lambda実行時間の増加: 月間+500 GB秒（無料枠内）
- API Gateway呼び出し: 月間+1,000リクエスト（無料枠内）
- 追加コスト: $0.00（無料枠内で運用可能）
