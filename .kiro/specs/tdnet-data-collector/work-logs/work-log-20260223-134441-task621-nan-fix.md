## 作業概要

本番環境でのStep Functions実行テスト時に発見された`collector-aggregate`の`progress`計算でのNaN発生問題を修正します。

## 問題の詳細

### エラー内容
```
Error: Special numeric value NaN is not allowed
at convertToNumberAttr (/var/runtime/node_modules/@aws-sdk/util-dynamodb/dist-cjs/index.js:213:11)
at marshall (/var/runtime/node_modules/@aws-sdk/util-dynamodb/dist-cjs/index.js:313:26)
at update-execution-status.ts:154:15
at collector-aggregate/handler.ts:125:5
```

### 根本原因
`collector-aggregate`で`progress`を計算する際に、`collected_count / estimated_total`が`NaN`になっている。
これは`estimated_total`が0または未定義の場合に発生する。

### 影響範囲
- Step Functions実行が失敗
- データ収集は部分的に成功している可能性があるが、集約処理が完了していない

## 実施内容

### 1. collector-aggregateの修正

`progress`計算時にNaN発生を防ぐため、デフォルト値を設定します。

### 2. update-execution-statusの修正

NaN値のバリデーションを追加します。

### 3. テスト追加

`estimated_total`が0の場合のテストケースを追加します。

## 作業ログ


### 1. collector-aggregateの修正

**ファイル**: `src/lambda/collector-aggregate/handler.ts`

**修正内容**:
- `success_rate`計算後にNaN検証を追加
- `validSuccessRate`変数を導入し、`Number.isFinite()`でNaNをチェック
- NaNの場合は0にフォールバック
- すべての使用箇所で`validSuccessRate`を使用

**修正箇所**:
```typescript
// 統計情報の計算
const totalCount = total_collected + total_failed;
const success_rate = totalCount > 0 
  ? (total_collected / totalCount) * 100 
  : 0;

// NaN防止: success_rateが有効な数値であることを確認
const validSuccessRate = Number.isFinite(success_rate) ? success_rate : 0;
```

### 2. update-execution-statusの修正

**ファイル**: `src/lambda/collector/update-execution-status.ts`

**修正内容**:
- `progress`, `collected_count`, `failed_count`のNaN検証を追加
- `Number.isFinite()`で各パラメータをチェック
- NaNが検出された場合は明確なエラーメッセージをスロー

**修正箇所**:
```typescript
// NaN検証: 数値パラメータが有効であることを確認
if (!Number.isFinite(clampedProgress)) {
  throw new Error(`Invalid progress value: ${progress} (resulted in ${clampedProgress})`);
}
if (!Number.isFinite(collected_count)) {
  throw new Error(`Invalid collected_count value: ${collected_count}`);
}
if (!Number.isFinite(failed_count)) {
  throw new Error(`Invalid failed_count value: ${failed_count}`);
}
```

## 6. collector-aggregateのデータ形式修正

### 問題の根本原因
Step FunctionsのMap状態から渡されるデータ形式と、collector-aggregateハンドラーが期待するデータ形式が不一致でした。

**Map状態の出力形式**:
```json
[
  {
    "saveResult": {
      "page_number": "2024-01-15",
      "saved_count": 100,
      "failed_count": 0
    }
  }
]
```

**collector-aggregateが期待していた形式**:
```json
[
  {
    "date": "2024-01-15",
    "success_count": 100,
    "failed_count": 0
  }
]
```

### 修正内容

#### 1. AggregateEventインターフェースの修正
Map状態の実際の出力形式に合わせてインターフェースを修正しました。

#### 2. aggregateResults関数の修正
- `saveResult`が存在する場合のみ集約（失敗したページは`saveResult`がない）
- `saved_count`と`failed_count`のNaN検証を追加
- NaNの場合は0にフォールバック

#### 3. テストケースの修正
- すべてのテストケースを新しいデータ形式に更新
- `saveResultがないページを無視する`テストケースを追加
