# TDnet Data Collector - タスク実行ルール

**重要: すべての作業は日本語で実施してください**

## 実行原則

**設計 → 実装 → テスト → デプロイ の順序を厳守し、各フェーズで品質を確保**

### 禁止事項
- ❌ 設計書なしでの実装開始
- ❌ テストなしでのデプロイ
- ❌ ドキュメント未更新での完了報告

## タスク実行チェックリスト

### 開始時（設計フェーズ）
- [ ] タスク分析・理解
- [ ] 要件の明確化（曖昧な点は質問）
- [ ] 依存関係の確認（前提タスクの完了状態）
- [ ] 影響範囲の特定（変更が波及するファイル・機能）
- [ ] コードベース調査（必要時context-gatherer使用）
- [ ] 設計書作成（`.kiro/specs/tdnet-data-collector/02-design/`）
  - インターフェース定義
  - データフロー図
  - エラーハンドリング戦略
  - テスト戦略
- [ ] 設計書のセルフレビュー
- [ ] 作業記録作成: `.kiro/specs/tdnet-data-collector/work-logs/work-log-[YYYYMMDD-HHMMSS]-[作業概要].md`
  - 時刻: `Get-Date -Format "yyyyMMdd-HHmmss"`（推測禁止）
  - 作業概要: ケバブケース（例: `lambda-error-handling`）
  - 文字エンコーディング: UTF-8 BOMなし（すべてのファイル作成・編集時）

### 実行中（実装フェーズ）
- [ ] 設計書に基づいた実装
- [ ] コーディング規約の遵守（`tdnet-implementation-rules.md`）
- [ ] 定数管理の徹底（マジックナンバー禁止）
- [ ] エラーハンドリングの実装（`error-handling-patterns.md`）
- [ ] 実装のセルフレビュー
  - [ ] ハードコーディングの排除
  - [ ] エラー分類の適切性
  - [ ] ログ出力の構造化
  - [ ] 型安全性の確保
- [ ] 問題と解決策を作業記録に追記

### テストフェーズ
- [ ] ユニットテスト作成・実行
  - [ ] 正常系テスト
  - [ ] 異常系テスト（Retryable/Non-Retryable/Partial Failure）
  - [ ] エッジケーステスト
- [ ] テストカバレッジ確認（80%以上推奨）
- [ ] 統合テスト実行（該当する場合）

### E2Eテスト実行時（該当する場合）
- [ ] Docker Desktop起動確認: `docker ps`
- [ ] LocalStack環境起動: `docker compose up -d`
- [ ] LocalStack環境確認: `docker ps --filter "name=localstack"`
- [ ] DynamoDB/S3リソース確認: `scripts/localstack-setup.ps1`
- [ ] E2Eテスト実行: `npm run test:e2e`
- [ ] テスト結果の確認・記録

### デプロイ前チェック（本番反映時）
- [ ] すべてのテスト成功確認
  - [ ] ユニットテスト: `npm test`
  - [ ] E2Eテスト: `npm run test:e2e`（該当する場合）
- [ ] 静的解析クリア: `npm run lint`
- [ ] 型チェック成功: `npm run type-check`
- [ ] ドキュメント更新確認
  - [ ] README.md
  - [ ] API仕様書
  - [ ] 設計書
- [ ] ロールバック手順の確認
- [ ] 環境変数・設定の確認
- [ ] AWS認証確認: `aws sts get-caller-identity --profile imanishi-awssso`

### 運用スクリプト実行時（必須）
- [ ] AWS認証確認: `aws sts get-caller-identity --profile imanishi-awssso`（必要に応じて`aws sso login`）
- [ ] 環境指定: `-Environment`パラメータで環境を指定（dev/prod、デフォルト: prod）
- [ ] プロファイル指定: `-Profile`パラメータでAWS CLIプロファイルを指定（デフォルト: imanishi-awssso）
- [ ] 環境情報は自動取得: CDK Outputsから自動取得されるため、ハードコーディング不要
- [ ] エラー発生時: エラーメッセージの指示に従って対処（AWS認証、スタック存在確認等）

### 完了時
- [ ] 最終レビュー
  - [ ] コード品質の確認
  - [ ] テストカバレッジの確認
  - [ ] ドキュメントの完全性確認
- [ ] 作業記録に成果物・申し送り記入
- [ ] **タスク完了条件の確認**:
  - [ ] **設計書作成**: 実装前に設計書を作成し、レビュー済み
  - [ ] **実装完了**: 設計書に基づいた実装が完了
  - [ ] **テスト成功**: 関連するユニットテスト（UT）を修正し、再実行して成功を確認（必須）
  - [ ] **静的解析クリア**: ESLint、TypeScriptコンパイラエラーなし
  - [ ] **関連ドキュメント・テストの更新**: 当該タスクの変更によって影響を受けるドキュメントやテストを修正
  - [ ] **修正が間に合わない場合**: 新規タスクを作成して追跡（tasks.mdに追加）
- [ ] Git commit & push（形式: `[feat/fix/docs/refactor/test/chore/improve] 変更内容`）
- [ ] 問題発生時: 改善記録作成（`.kiro/specs/tdnet-data-collector/improvements/task-[番号]-improvement-[連番]-[YYYYMMDD-HHMMSS].md`）
- [ ] ファイルエンコーディング確認: すべてのファイルがUTF-8 BOMなしであることを確認（`file-encoding-rules.md`参照）

## 品質ゲート

各フェーズで以下の品質基準を満たさない場合、次フェーズに進めません：

### 設計フェーズ
- ✅ 要件が明確に定義されている
- ✅ インターフェースが明確に定義されている
- ✅ エラーハンドリング戦略が策定されている
- ✅ テスト戦略が策定されている
- ✅ 依存関係が明確になっている

### 実装フェーズ
- ✅ 設計書に基づいた実装である
- ✅ コーディング規約を遵守している
- ✅ ハードコーディングがない
- ✅ エラーハンドリングが適切に実装されている
- ✅ 型安全性が確保されている

### テストフェーズ
- ✅ ユニットテストが作成されている
- ✅ 正常系・異常系・エッジケースがカバーされている
- ✅ テストカバレッジが80%以上である
- ✅ すべてのテストが成功している
- ✅ 静的解析がクリアしている

### デプロイフェーズ
- ✅ すべてのテストが成功している
- ✅ ドキュメントが更新されている
- ✅ ロールバック手順が確認されている
- ✅ 環境変数・設定が正しい
- ✅ レビューが完了している

## サブエージェント活用（Autopilotのみ）

### 利用可能
- **context-gatherer**: コードベース探索
- **general-task-execution**: 独立サブタスク委譲
- **custom-agent-creator**: 繰り返しタスク自動化

### タスク依存関係の考慮（重要）

サブエージェントにタスクを委譲する前に、必ず以下を確認してください：

#### 1. 依存関係の確認
- [ ] **前提タスク**: 実行予定のタスクが依存する他のタスクが完了しているか確認
- [ ] **ブロッカー**: 未完了の前提タスクがある場合、先にそれらを完了させる
- [ ] **並列実行可能性**: 依存関係のないタスクのみ並列実行可能

#### 2. 依存関係の種類
- **技術的依存**: コード変更が他のタスクの前提となる（例: インターフェース定義 → 実装）
- **データ依存**: データ構造やスキーマ変更が他のタスクに影響する
- **設定依存**: 環境変数や定数の変更が他のタスクに影響する
- **テスト依存**: テストフレームワークやモックの変更が他のテストに影響する

#### 3. 依存関係の確認方法
```markdown
# tasks.mdで確認
- タスクの「依存」セクションを確認
- 「ブロック」セクションで他タスクへの影響を確認
- 関連タスクの完了状態を確認
```

#### 4. 実行順序の決定
1. **依存関係グラフを作成**: タスク間の依存関係を可視化
2. **実行順序を決定**: 依存関係に基づいて実行順序を決定
3. **並列実行グループを特定**: 依存関係のないタスクをグループ化
4. **順次実行**: 依存関係のあるタスクは順次実行

#### 5. 依存関係違反の防止
- [ ] **実行前チェック**: 前提タスクの完了を確認してから実行
- [ ] **エラー検出**: 依存関係違反を検出した場合、即座に停止
- [ ] **ロールバック**: 依存関係違反が発生した場合、変更をロールバック
- [ ] **再計画**: 依存関係を考慮して実行計画を再作成

### サブエージェント実行時の必須指示
1. **設計フェーズ**: 設計書作成（`.kiro/specs/tdnet-data-collector/02-design/`）
2. **実装フェーズ**: 設計書に基づいた実装
3. **テストフェーズ**: ユニットテスト作成・実行
4. 作業記録作成（上記形式）
5. tasks.md更新（[ ]→[x]、完了日時・テスト結果追記）
6. **依存関係の確認**: 前提タスクの完了状態を確認
7. **依存関係の記録**: 作業記録に依存関係を明記
8. **品質ゲートの遵守**: 各フェーズの品質基準を満たすこと

### メインエージェントの責任
- サブエージェント作業記録確認
- **品質ゲートの検証**: 各フェーズの品質基準が満たされているか確認
- **設計書レビュー**: 実装前に設計書の妥当性を確認
- **テスト結果レビュー**: すべてのテストが成功しているか確認
- メイン記録にリンク追加
- Git commit
- tasks.md更新確認
- **依存関係の検証**: サブエージェントが依存関係を正しく考慮したか確認
- **影響範囲の確認**: 変更が他のタスクに与える影響を評価
