# TDnet Data Collector - タスク実行ルール

**重要: すべての作業は日本語で実施してください**

## 実行原則

**設計 → 実装 → テスト → デプロイ の順序を厳守し、各フェーズで品質を確保**

### 禁止事項
- ❌ 設計書なしでの実装開始
- ❌ テストなしでのデプロイ
- ❌ ドキュメント未更新での完了報告

## フェーズ別チェックリスト

### 1. 設計フェーズ
- [ ] タスク分析・依存関係確認（tasks.mdで前提タスクの完了状態を確認）
- [ ] 要件明確化・影響範囲特定（必要時context-gatherer使用）
- [ ] 設計書作成（`.kiro/specs/tdnet-data-collector/02-design/`）
  - インターフェース定義、データフロー、エラーハンドリング戦略、テスト戦略
- [ ] 作業記録作成: `work-log-[YYYYMMDD-HHMMSS]-[作業概要].md`
  - 時刻: `Get-Date -Format "yyyyMMdd-HHmmss"`（推測禁止）
  - UTF-8 BOMなし

**品質ゲート**: 要件・インターフェース・エラーハンドリング・テスト戦略が明確に定義されている

### 2. 実装フェーズ
- [ ] 設計書に基づいた実装
- [ ] コーディング規約遵守（定数管理、エラーハンドリング、型安全性）
- [ ] セルフレビュー（ハードコーディング排除、ログ構造化）

**品質ゲート**: 設計書準拠、コーディング規約遵守、ハードコーディングなし

### 3. テストフェーズ
- [ ] ユニットテスト作成・実行（正常系・異常系・エッジケース）
- [ ] カバレッジ確認（80%以上推奨）
- [ ] E2Eテスト（該当時）: LocalStack起動 → `npm run test:e2e`
- [ ] 静的解析: `npm run lint` + `npm run type-check`

**品質ゲート**: すべてのテスト成功、カバレッジ80%以上、静的解析クリア

### 4. デプロイフェーズ
- [ ] ドキュメント更新（README、API仕様書、設計書）
- [ ] AWS認証確認: `aws sts get-caller-identity --profile imanishi-awssso`
- [ ] 運用スクリプト実行時: `-Environment`（dev/prod）、`-Profile`指定

**品質ゲート**: すべてのテスト成功、ドキュメント更新完了、ロールバック手順確認済み

### 5. 完了時
- [ ] タスク完了条件確認（設計書作成済み、実装完了、テスト成功、静的解析クリア）
- [ ] 作業記録に成果物・申し送り記入
- [ ] Git commit: `[feat/fix/docs/refactor/test/chore/improve] 変更内容`
- [ ] 問題発生時: 改善記録作成（`.kiro/specs/tdnet-data-collector/improvements/`）

## サブエージェント活用（Autopilotのみ）

### 利用可能なサブエージェント
- **context-gatherer**: コードベース探索（タスク開始時に1回のみ使用推奨）
- **general-task-execution**: 独立サブタスク委譲
- **custom-agent-creator**: 繰り返しタスク自動化

### タスク依存関係の管理

**委譲前の必須確認**:
- [ ] tasks.mdで前提タスクの完了状態を確認
- [ ] 未完了の前提タスクがある場合、先に完了させる
- [ ] 依存関係のないタスクのみ並列実行可能

**依存関係の種類**:
- 技術的依存: インターフェース定義 → 実装
- データ依存: スキーマ変更が他タスクに影響
- 設定依存: 環境変数・定数変更が他タスクに影響
- テスト依存: テストフレームワーク変更が他テストに影響

### サブエージェント実行時の指示事項
1. 設計書作成（`.kiro/specs/tdnet-data-collector/02-design/`）
2. 設計書に基づいた実装
3. ユニットテスト作成・実行
4. 作業記録作成（上記形式）
5. tasks.md更新（[ ]→[x]、完了日時・テスト結果追記）
6. 依存関係の確認・記録

### メインエージェントの責任
- 品質ゲートの検証（各フェーズの基準を満たしているか）
- 設計書・テスト結果のレビュー
- 依存関係の検証（サブエージェントが正しく考慮したか）
- 影響範囲の確認（変更が他タスクに与える影響）
- Git commit、tasks.md更新確認
